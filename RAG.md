# @civitas-cerebrum/element-repository — AI Reference
**Purpose:** A JSON-based locator repository for Playwright (web) and WebdriverIO/Appium (android, ios). Selectors live in a JSON file, not in test code; tests look elements up by `elementName` + `pageName` and get a unified `Element` (`WebElement` wrapping a Playwright `Locator`, or `PlatformElement` wrapping WebdriverIO `$` / `$$`).
## JSON Schema
- `pages[]`: `{ name, platform?, frame?, frameIndex?, elements[] }`. `platform` missing = `web` (see Platforms). `frame` (web only) = `{ css? | xpath? }` or an array of them for nested iframes; `frameIndex` = `"first"` / `"last"` / integer when several frames match.
- `elements[]`: `{ elementName, selector, list?, provisional? }`. `list: true` = a collection (contract: at least one match); `provisional: true` = not yet confirmed against the app. Both JSON booleans, default `false`; resolution ignores them (read via `getElementMeta` / `getProvisional`).
- `selector`: ONE selector key per object — only the first string-valued key is used (web: `css`, `xpath`, `id`, `text`, `testid`, `role`, `placeholder`, `label`; platform keys: see Platforms). Exception: enhanced `role` + `name` (+ optional `exact`) together. `text` / `name` also take `{ "regex": "...", "flags": "i" }`. Optional `fallback`: another selector object, recursive.
```json
{
  "pages": [
    {
      "name": "HomePage",
      "elements": [
        { "elementName": "categories", "list": true, "selector": { "css": ".category-card" } },
        { "elementName": "login", "selector": { "css": "[data-qa='login']", "fallback": { "role": "button", "name": { "regex": "Log in|Anmelden", "flags": "i" } } } }
      ]
    },
    {
      "name": "PaymentPage", "frame": { "css": "iframe.payment" }, "frameIndex": "first",
      "elements": [ { "elementName": "cardNumber", "provisional": true, "selector": { "css": "input[name='card']" } } ]
    }
  ]
}
```

## Setup
```ts
// Constructor: (driver, fileOrData: string | PageRepository | PageRepositoryInput, options?: number | { platform?: Platform; defaultTimeout?: number; timeout?: number })
// driver = Playwright Page (web) or WebdriverIO Browser from remote() (android/ios). A number = timeout ms. Default timeout 15000.
// `timeout` is an alias of `defaultTimeout`; when both are given, `defaultTimeout` wins.
const repo = new ElementRepository(page, 'tests/data/page-repository.json', 15000);
```

## Usage Example
```ts
const repo = new ElementRepository(page, 'tests/data/page-repository.json');
const forms = await repo.getByText('categories', 'HomePage', 'Forms'); // Element | null
await forms?.click();
const cards = await repo.getAll('categories', 'HomePage');             // Element[]
const login = await repo.get('login', 'HomePage');                     // Element (falls back if the css never attaches)
```

## API (`elementName` first, then `pageName`; `strict` defaults to `false`: `null` + warning when nothing matches, `true` throws)
- `get(elementName, pageName, options?: ElementResolutionOptions): Promise<Element>` — first match by default. `options`: `{ strategy?: SelectionStrategy, value?, attribute?, index?, timeout?, signal? }` (`ElementResolutionOptions extends LookupOptions { signal?: AbortSignal }`); `SelectionStrategy` = `INDEX` / `TEXT` / `ATTRIBUTE` / `RANDOM` / `ALL` (an unhandled one, e.g. `VALUE`, throws).
- `getAll(elementName, pageName, options?: LookupOptions): Promise<Element[]>` — every match.
- `getRandom(elementName, pageName, strict?, options?: LookupOptions): Promise<Element | null>` — random match (waits for one to be visible).
- `getByText(elementName, pageName, desiredText, strict?, options?: LookupOptions): Promise<Element | null>` — trimmed `textContent()` exact match first, then contains (platform: the text rule under PlatformElement). iOS / Android: narrowed like `TEXT` (see "TEXT narrowing"), its own comparison (exact, case-sensitive contains) applied to the hits; compares every match when not narrowable, on a narrowed-query error (lost session thrown) or iOS cross-query winners.
- `getByAttribute(elementName, pageName, attribute, value, options?: { exact?: boolean; strict?: boolean; signal?: AbortSignal }): Promise<Element | null>` — `exact` omitted: exact then contains.
- `getByIndex(elementName, pageName, index, strict?, options?: LookupOptions): Promise<Element | null>` — zero-based; out of range → `null` (or throws if strict).
- `getVisible(elementName, pageName, strict?, options?: LookupOptions): Promise<Element | null>` — first match with `isVisible()`.
- `getByRole(elementName, pageName, role, strict?, options?: LookupOptions): Promise<Element | null>` — `role` attribute, exact.
- **Cancelling (`signal`, every getter):** once aborted, no further driver call of the LOOKUP starts (queries, narrowed queries, text/attribute/visibility reads, attach waits, each fallback node, inter-poll sleeps wake at once); a call already running may finish, its result is dropped; reads issued together are all awaited before rejecting. Rejects with `LookupAbortedError` (`cause` = `signal.reason`); an abort never walks the fallback chain. Returned elements do NOT carry the signal (they keep working after it fires). Abort wins over not-found: non-strict getters reject, not `null`. Repository/argument errors come first (even with an already aborted signal); a fatal driver error seen before the abort is thrown as is; an already aborted signal makes no driver call. Web: Playwright waits are raced (the lookup rejects at once; the abandoned wait ends on its own timeout). Hard stop: `AbortSignal.timeout(ms)` / `AbortSignal.any([s, AbortSignal.timeout(ms)])`. Without a signal nothing changes.
- `getElementMeta(elementName, pageName): ElementMeta` — **sync**, `{ provisional, list }` with defaults.
- `getProvisional(): Array<{ pageName, elementName }>` — **sync**, entries with `provisional: true` (active platform only, if set).
- `getSelector(elementName, pageName): string` — **sync**, platform-formatted selector (e.g. `css=.btn`, `~login-submit`).
- `getSelectorRaw(elementName, pageName): { strategy: string; value: string }` — **sync**, unformatted.
- `getPagePlatform(pageName): Platform` — **sync**, page's platform (`'web'` when missing).
- `static validate(data: PageRepository | PageRepositoryInput): void` — throws `ElementRepository: invalid repository — <problems>.`; the constructor runs it.
- `setDefaultTimeout(timeout: number): void`.
- `driver` (getter) — the driver passed in. `platform` (getter) — active `Platform` or `undefined`.
- Lookup errors: unknown element → `ElementRepository: Element '<el>' not found on page '<page>'.`; unknown page → see Platforms (Lookup rule).

## Platforms (0.4.0+)
- **Vocabulary:** `type Platform = 'web' | 'android' | 'ios' | 'macos' | 'windows'`; `type DriverFamily = 'playwright' | 'appium'`; `PLATFORMS` (frozen array); `isPlatformName(v)` (exact, case-sensitive); `familyOf(p)` — `web` → `playwright`, rest → `appium`; an unknown value (in `familyOf` or the constructor's `options.platform`) throws `ElementRepository: unknown platform '<v>'. Expected one of: web, android, ios, macos, windows.` `macos` / `windows` are declared, not implemented yet (base Appium formatters).
- **Two meanings of "platform":** the `Platform` type is the page/run platform and INCLUDES `web`. `PlatformElement`, `isPlatform(el)`, `ElementType.PLATFORM` mean the non-web (WebdriverIO/Appium) backend: `isPlatform(webElement)` is `false`.
- **JSON:** one file may hold the same page `name` once per platform. `"platform"` missing = `web`. Same `elementName` per logical element on every platform. Invalid platform (e.g. `"mobile"`), duplicate `name`+`platform`, or `frameIndex` other than `"first"`/`"last"`/integer → constructor throws `ElementRepository: invalid repository — ...`.
```json
{ "pages": [
  { "name": "LoginPage", "platform": "web",     "elements": [ { "elementName": "submit", "selector": { "css": "button[type=submit]" } } ] },
  { "name": "LoginPage", "platform": "android", "elements": [ { "elementName": "submit", "selector": { "accessibility id": "login-submit" } } ] },
  { "name": "LoginPage", "platform": "ios",     "elements": [ { "elementName": "submit", "selector": { "accessibility id": "login-submit" } } ] }
] }
```
- **Constructor** (signature: see Setup): `options.platform` sets the ACTIVE platform; a WebdriverIO `Browser` from `remote()` is the driver for android/ios. `repo.platform` = active platform or `undefined`.
```ts
const repo = new ElementRepository(driver, 'tests/data/page-repository.json', { platform: 'ios' });
const submit = await repo.get('submit', 'LoginPage'); // the "ios" LoginPage block
```
- **Lookup rule:** active platform set → page with matching `name` AND `(platform ?? 'web') === active`, else throws `ElementRepository: page '<name>' has no entry for platform '<active>'. Available: <list>.` (`<list>` = platforms declaring the page, or `none`). No active platform → first page with that name, else `ElementRepository: Page '<name>' not found.` No cross-platform fallback; no global state.
- **Selector keys on platform pages:** `accessibility id` (`~v`), `id`, `xpath`, `class name`, `uiautomator` (`android=v`), `predicate` (`-ios predicate string:v`), `class chain` (`-ios class chain:v`), `text`, enhanced `role` + `name`.
  - `id`: android → `id=v` (resource-id; a short id gets the app package prefix); ios → predicate `name == "v"`; macos/windows → `~v`. Never CSS.
  - `text`: android → `UiSelector().text("v")` (only `"` escaped; a value ending in `\` cannot be expressed — the formatter throws and points to `xpath`); ios → predicate `label == "v"`.
- **Strategies on platform pages:** default = first match (`count()`/`all()` on it return at most 1; use `getAll` / `SelectionStrategy.ALL` to count). `TEXT` compares each match's OWN text, read with the `textContent()` rule (see PlatformElement; the selector must target the text-bearing element, or (iOS and Android) a container without own text, which reads its descendants' joined text; a container row costs 2 + K round trips, a big container reads every text inside it, a descendant whose own text repeats its children's is counted twice (rare)), exact then case-insensitive contains, polls up to the full timeout; each poll = one `$$` pass that reads EVERY match (exact match ends it early), the deadline only decides whether another pass starts, so the last pass of a long list may overrun the timeout by up to one pass (a small budget still finds a late item); the overrun scales with match count × per-row cost (1 read per row, 2 + K per container row) and applies per fallback node (each `fallback` node tried runs its own full-timeout TEXT poll); that pass cost applies only to polls that are not narrowed (below). A blank `TEXT` value throws (web too).
- **TEXT narrowing (iOS, Android; also `getByText`):** a poll first queries only a SUPERSET of the matches the rule could choose, then applies the unchanged rule (exact beats contains, document order) to those hits. Words = distinct words of `normalise(value)` (`\s+`→space incl. NBSP/newline, trim, lowercase) that are safe for the platform, longest first, at most 4 (the longest kept; unsafe ones left out); a hit holds EVERY word; any text containing the value contains each word, so nothing is lost ("Item 9" among "Item N - …" rows → only the Item 9 row; "item" alone → every row). Android: ONE XPath `(<base>)[(c1 and … and cn) or (.//*[nh and c1] and … and .//*[nh and cn])]` (no parens for one word), `ck` = `contains(LCk(@text),'wk')`, `nh` = `not(@showing-hint='true')` (words may sit in different descendants), `LCk` = `translate()` over every char that lowercases to a char of word k (K + Kelvin sign, I + İ, Å + Angstrom sign, …), literal `'…'` / `"…"` / `concat()`; base = XPath as is (parenthesised), full resource id → `//*[@resource-id='…']`, accessibility id → `//*[@content-desc='…']`, class name → `//<class>`; hits are in document order = the full-pass answer. iOS: TWO disjoint queries, own = ``<chain>[`(label CONTAINS[cd] "w1" AND … AND label CONTAINS[cd] "wn") OR (value CONTAINS[cd] "w1" AND … AND value CONTAINS[cd] "wn")`]`` (one word: `label CONTAINS[cd] "w1" OR value CONTAINS[cd] "w1"`; every word in ONE attribute, as the rule reads one; covers text inputs' value-first rule), descendant = ``<chain>[`NOT (L)`][$type == "XCUIElementTypeStaticText" AND (L)$]`` with L = `label CONTAINS[cd] "w1" OR value CONTAINS[cd] "w1"` (longest word only; disjoint because every own hit has an attribute holding w1); base = class chain (appended to its last segment; last segment ending in an index `[2]`/`[-1]` → not narrowed, WDA takes no predicate after a position), accessibility id → ``**/*[`name == "…"`]``, class name → `**/<type>`, predicate string → own `(<pred>) AND (own)` + descendant ``**/*[`<pred>`]…``; `\` and `"` escaped; winners (exact, else contains) from BOTH queries → that poll is a full pass (cross-query order unknown). No hit = clean miss for the poll, polling continues (a miss poll = 1 query Android / 2 iOS; a hit = those + the hits' reads). Faster: several words with one common to every row (now usually 1 query + 1 read Android, 2 queries + type/label reads iOS). Not faster: a one-word value every row contains (reads every hit), words left out (unsafe / past the 4 longest), iOS container rows (longest word only). Measured (median of 3, ms, previous release → this one, TEXT; full table in README): iOS sim 16 "Item N - Lorem ipsum dolor sit amet" cells: contains "item 9" 3587→551, absent (3 s timeout) 3791→3203, getByText absent 5062→1705, exact "Item 9 - Lorem…" 2605→2764 (not faster); iOS sim 18 option cells (child StaticText): last "United States" 13838→2394, absent 12844→3153; real Android 11 rows (child views): last "Item 11 Gamma" 2527→620, absent 4427→3285. Not faster: >4 words where all but a short distinguishing one are in every row (the 4 longest shared → all rows read, ~2.6–3.8 s, slightly slower), a one-word value in every row, iOS container rows (longest word only). A NARROWED absent lookup now ends close to its timeout (each poll = only the native queries; before, a started pass could overrun it by many seconds); a lookup running the FULL pass (not narrowable, no safe word, narrowed query failed, iOS winners from both queries) may still overrun its timeout by up to one pass. Not narrowed (full pass every poll): platform not ios/android, base kind not composable (UiAutomator, short resource id (needs app package), iOS XPath, matchers, …), no safe word (iOS: only words whose every char is Latin / Greek / Cyrillic / Han / Hiragana / Katakana (+ U+30FC) / precomposed Hangul syllable / ASCII digit / ASCII punctuation except backtick and `$`, and no grapheme extender (CONTAINS matches whole composed chars); residual: a safe word next to a combining mark in decomposed text relies on `[cd]` dropping Latin/Greek/Cyrillic diacritics; Android: σ/ς, U+0307; both: control chars, lone surrogates; Android: a cased astral char). Narrowed-query error: lost session/connection (internal `isSessionLostError`, not exported: invalid session id, session not created, terminated/not started, ECONNREFUSED/ECONNRESET/ENOTFOUND/EPIPE, UiAutomator2 instrumentation not running) is thrown; any other error (incl. `invalid selector` / `invalid argument`) → this and every later poll of the lookup is a full pass; the error is NOT reported (not in the message, not `lastDriverError`; only the full passes' own errors are). iOS `value CONTAINS` on a non-string value (switch/slider) may fail the narrowed query → full pass (slower, same answer). Known limit (Android): narrowed XPath runs on the page source capped by `snapshotMaxDepth` (default 70); a deeper match is not found by a narrowed lookup (clean miss per poll); raise `appium:snapshotMaxDepth`. The result keeps the base selector (`all()` / `count()` unchanged).
- **Fallback:** primary not attached within `options.timeout ?? defaultTimeout`, or primary throws during resolution (platform TEXT, ATTRIBUTE / RANDOM / INDEX with no match) → walks `selector.fallback`; if the whole chain fails, the primary's error is rethrown.
- **Element primitives:** every interaction takes an optional `{ timeout? }` and returns `Promise<Element>` (the element itself), gestures included.
  - `click({ withoutScrolling?, timeout? })` (`ClickOptions`) — `withoutScrolling` on web: wait attached, then dispatch a DOM `click` (no scrolling, no actionability checks); on platform it changes nothing: a platform click is always the plain WebDriver element click, which never scrolls.
  - `longPress({ duration = 1000, timeout? })` — platform: touch down / pause / up; web: mouse hold.
  - `tapAt({ x, y }, { timeout? })` — px from the top-left, inside the bounds; web: `click({ position })`.
  - `pinch({ scale = 0.5, timeout? })` — scale in (0, 1); `zoom({ scale = 2, timeout? })` — scale > 1. Platform only; web throws `PlatformNotSupportedError`.
  - `scrollIntoView({ direction = 'down', maxSwipes = 20, container?, timeout? })` — platform: no attach wait, one-direction sweep of at most `maxSwipes` swipes; swipe line: with `container` (a platform element by `isPlatform`, so another package copy's works; else refused) inside its window-clipped rect, 85%→15% of its width (left/right, at its vertical centre) or height (up/down, at its horizontal centre), read once, not found / off-window fails before any swipe, as a drag that lifts a still finger (`SWEEP_HOLD_MS` 50, `SWEEP_MOVE_MS` 300, `SWEEP_RELEASE_HOLD_MS` 200 hold before lift): no fling, so a paging scroller as wide as the container advances one page (drag > half a page) and a free list in it moves 70% of it; a drag reaching into the 10% window edge bands (`SWEEP_EDGE_BAND`) is shifted whole into the container's part between them when it fits, else stays at the container's own 85%/15%; travel under half the container (too thin at the edge) throws `scrollIntoView: container "<sel>" is too close to the window edge to sweep` (no long press); without `container` 75%→25% of the window (`SWIPE_HOLD_MS` 100, `SWIPE_MOVE_MS` 600, no end hold; for free-scrolling lists; a paging carousel needs `container`) along the target's own centre row/column (re-read each swipe) while the target is in the tree and the line is in the window, else the window centre — pass `container` for an off-centre carousel/list whose off-screen items are not in the tree; the line is kept between 10% and 90% of the window; points rounded, clamped to `[0, size-1]`; `SWIPE_SETTLE_MS` 200 after each swipe; web ignores `container`; ONLY a `timeout` passed to the call bounds it by time (no new swipe after the deadline, so it can overrun by one swipe); without one only the swipe limit applies (the default timeout does not). Web ignores `direction` / `maxSwipes`; Playwright timeout = `options.timeout ?? ` the element's default timeout (the repository default). Every backend throws for a `maxSwipes` that is not a positive integer. `swipe(direction, { distance?, timeout? })` — platform: waits attached, end point clamped to the window `[0, width-1]` x `[0, height-1]`, start point unchanged; web: waits visible.
  - Platform gestures and swipe use native-context viewport coordinates; the point must be inside the window (scroll first).
  - `ElementChain` has `scrollIntoView(options?)`, `swipe(direction, options?)`, `longPress`, `tapAt`, `pinch`, `zoom`. It never branches on the backend: `scrollIntoView` / `swipe` do not wait in the chain (the element waits for itself); the four gestures wait for visible first; `click({ withoutScrolling })` waits attached and passes the option to `element.click`, as `clickIfPresent({ withoutScrolling })` does. An explicit `options.timeout` overrides the chain timeout; otherwise the chain timeout is passed on — except `scrollIntoView`, which passes its options on as given; the chain timeout is never applied to `scrollIntoView`, so a web `action(t).scrollIntoView()` uses the repository default timeout, not `t`.
- **PlatformElement:** `first()` / `nth(i)` index for real, lazily (negative counts from the end; non-integer throws). `first()` / `nth(0)` use WebdriverIO `$` and its waiting (except on a `locateChild` child, which is always polled with `$$`); other indexes poll `$$`: actions wait up to their `timeout`, reads up to the default timeout, then throw `nth(<i>): no element at that index for "<selector>" (found <n>)`; `isVisible()` / `exists()` do not wait (`false`). On an already-single match (from `first`/`nth`/`all()`): `first()`, `nth(0)`, `nth(-1)` return itself; any other index matches nothing (`count()` 0, `exists()` / `isVisible()` false, actions and reads fail at once with `nth(<i>): "<selector>" is already a single match, so this index matches nothing`). `locateChild(sel)` searches inside the parent's match, honouring its index; every child is polled: actions wait up to their `timeout`, reads up to the default timeout, then fail naming the missing element (`parent "<selector>" not found`, `no element matches "<child>" inside "<parent>"`, or the parent's out-of-range error); a child of a missing parent has `count()` 0 and `isVisible()` / `exists()` false without waiting. `filter({ hasText })` (any criterion), `setInputFiles`, `dispatchEvent` throw `PlatformNotSupportedError`; an empty filter returns the element.
- **Platform text:** `textContent()` = trimmed visible text or `null`. iOS: `label`, then `value`; text inputs (TextField, SecureTextField, TextView, SearchField) `value` first, then `label`; neither has text (not an input) → the `XCUIElementTypeStaticText` descendants (class chain `-ios class chain:**/XCUIElementTypeStaticText` from the element, `IOS_DESCENDANT_TEXT_SELECTOR`, document order), each `label` else `value`, trimmed, blanks skipped, joined with single spaces (a dropdown option Cell with a child StaticText `Banana` → `Banana`); not filtered by visibility; a button's or input's own label/value is not read (only StaticText); a StaticText or Image with empty label/value makes no query; cost: one query + one label read per StaticText, only in that case; none → own (empty) text; avoid `TEXT` on a bare `XCUIElementTypeOther` selector (each match reads every StaticText under it). One rule: an element's text is its own, else its descendants'. Android: driver `getText()`; when that is empty/whitespace, the descendants' non-empty `text` values, hints excluded (XPath `.//*[@text!='' and not(@showing-hint='true')]`, a find-elements from the element, document order, each trimmed, not filtered by `displayed`) joined with single spaces (row `text=""` with children `Item 1`, `Alpha` → `Item 1 Alpha`); cost: one extra query + one read per text-bearing descendant (2 + K in all), only when own text is empty; every descendant is read; no descendant text → own text. Other: driver `getText()`. `rawText()` = same, untrimmed (web: DOM `textContent`). The `TEXT` strategy and `getByText` use the same rule.
- **Platform checked state:** `isChecked()` — Android: attribute `checked === "true"` (UiAutomator2 `selected` stays `"false"` on checked controls); iOS: `XCUIElementTypeSwitch` / `XCUIElementTypeToggle` → `value` `"1"`/`"true"`, any other type → `isSelected()` (a row's `value` may be a badge, never state); other platforms: `isSelected()`. `check()` / `uncheck()` use the same read (iOS: element type read once per call) and do nothing when the state matches; otherwise Android fails at once without a click for `checkable="false"` (`check: "<selector>" is not checkable`) and for `uncheck()` on a checked `android.widget.RadioButton` (`uncheck: "<selector>" is a radio button; select another option instead`); then `isEnabled()` is polled within the action timeout (still disabled → `check: "<selector>" is disabled`, no click); then one click and the state is polled within the same timeout (from the call's start, at least one read): `check: "<selector>" is still unchecked after clicking` / `uncheck: "<selector>" is still checked after clicking`.
- **Platform read of a missing element:** `textContent`, `rawText`, `getAttribute`, `getTagName`, `isEnabled`, `isChecked` (and `inputValue` on iOS) throw `<method>: "<selector>" not found within N ms: <reason>`; default-resolved: reason = WebdriverIO's `Can't call ... because element wasn't found`, N = driver `waitforTimeout` (omitted if unknown), WebdriverIO error as `cause`; indexed/child: N = element timeout; an element that matches nothing fails at once without `within N ms`. Gestures: `<method>: "<selector>" not found within N ms`; indexed/child gestures append `: <reason>`; a gesture on an element that matches nothing omits `within N ms`. Errors name an element `"<selector>"`; only an explicit `nth(i)` with i ≠ 0 reads `nth(<i>) of "<selector>"` (a plain repository lookup, `first()`, `nth(0)` do not); a child adds `inside <parent>`.
- **Platform element class:** `getTagName()` = iOS XCUITest type (`XCUIElementType*`), Android `class` attribute (`android.widget.*`; UiAutomator2's tag name is the content-desc or `null`, never used); the radio check and iOS text/switch rules read it the same way.
- **`doubleClick` on platform elements:** contract = a real double tap on the element (a double-tap recogniser fires; a plain button counts two taps). iOS: `driver.execute('mobile: doubleTap', { elementId })` (WebdriverIO's mouse double-click is one tap for XCUITest). Android: `driver.execute('mobile: doubleClickGesture', { elementId })` (WebdriverIO's 10 ms gap is below Android's 40 ms double-tap minimum). A missing element throws `doubleClick: "<selector>" not found within N ms` before anything is sent. iOS: WebDriverAgent scrolls a not-hittable element into view itself and fails (HTTP 500, passed through) when it still cannot hit it. Other platforms: WebdriverIO `doubleClick()`.
- **Unknown attribute name (android, ios):** `getAttribute(name)` returns `null` when the driver does not know the name at all — UiAutomator2 `'<name>' attribute is unknown for the element` (error `unknown command`, fatal for `isFatalDriverError`), XCUITest `The attribute '<name>' is unknown` (HTTP 500). Only that answer for that name is mapped; other errors are thrown. `getByAttribute` / `ATTRIBUTE` treat such elements as lacking the attribute; internal reads (checked, class, hint, iOS label / value) use the same mapping. A misspelt name reads as missing.
- **Android missing attribute:** UiAutomator2 returns the string `"null"` for an attribute an element lacks; `getAttribute()` maps it to `null`, so `getByAttribute` / `ATTRIBUTE` never match an element without the attribute, and `inputValue()` treats a `hint` of `"null"` as no hint. An attribute whose real value is the text `null` is indistinguishable from a missing one (same string) and also reads as `null`; `inputValue()` still returns `"null"` for a field holding that text.
- **Platform errors:** `getTagName()` throws for a missing element. `exists()` is `false` for a missing element but rethrows fatal driver errors (`isFatalDriverError`). `isVisible()` on a polled element (index other than the first match, `locateChild` child, matches-nothing): one lookup, no wait; real no-match (no element at the index, missing parent, `no such element` by error name or a message starting with the W3C phrase, not one quoting it deeper inside; WebdriverIO "wasn't found") = `false`; `stale element reference` = looked up and read once more; any other driver error (e.g. `unknown error`, a second stale in a row, fatal) is THROWN so a polling caller retries (so `isVisible()` / `clickIfPresent()` / `ElementChain.isPresent()` (returns `isVisible()`) may throw on a transient error for these elements). `waitFor({ state: 'hidden' | 'detached' })` on these elements: only a real no-match = gone; stale / other non-fatal error = undecided, keeps polling until the timeout; fatal = thrown; at the timeout it throws the last poll's driver error if that poll failed, else `<element> did not become hidden|detached within N ms`. Other platform elements: WebdriverIO `isDisplayed()`, errors passed through (unchanged).
- **`class LookupAbortedError extends Error { elementName?: string; pageName?: string; operation?: string; reason: unknown }`** (type `LookupAbortedErrorInit` = `{ elementName?, pageName?, operation?, reason }`; root and `types` exports): `name` = `'AbortError'`, `cause` = `reason`. Message `Lookup of '<el>' on '<page>' aborted.` or `waitFor on <element> aborted.` (`operation` text + ` aborted.`), plus ` (reason: <name>: <message>)` when `reason !== undefined`. `isFatalDriverError` is always `false` for it (whatever the reason says); never a `lastDriverError`, never retried. Single definition; re-export it.
- **`Element.waitFor({ state?, timeout?, signal? })`:** with `signal`, rejects with `LookupAbortedError` (`waitFor on <element> aborted.`); aborted signal = no driver call.
